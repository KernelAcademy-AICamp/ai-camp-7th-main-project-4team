핏팅(Fitting) — 브랜드를 가로질러 '내 사이즈'를 번역한다

2026-07-28 · 팀 3인(팀장·개발·디자인)
ONE LINE
"내 사이즈가 맞을까?"에서 멈추는 사람에게, 평소 입던 옷의 착용 경험만으로 새 브랜드의 내 사이즈를 알려주는 AI 진단 카드.
진단으로 사용자·사이즈 데이터를 모으고, 그 위에 전문가 매칭을 얹어 확장한다.
01 · 문제

새 브랜드로 건너가려는 사람은 거기서 내 사이즈가 뭔지를 몰라 망설인다. 기존 사이즈 추천은 자기 몰 안 + 구매 이력에 갇혀 있어, 새 몰·새 브랜드로 넘어가는 순간 아무도 번역해주지 않는다. 결국 늘 사던 브랜드의 비슷한 옷만 다시 산다.

구매를 막는 2축
스타일 어울림 40%
사이즈 적합 38%
— 설문. 반반이라 하나만 풀면 절반만 잡힌다
그래서 도구는 사이즈
스타일은 정답이 없다 → 전문가
사이즈는 정답이 있다 → 도구
지금의 심장 = 번역 엔진
02 · 타깃 · JTBD

김도현 / 33 / 직장인. 소개팅·미팅·발표처럼 잘 보이고 싶은 자리엔 기꺼이 지갑을 열지만, 안 입어본 브랜드는 사이즈가 두려워 결국 늘 사던 곳에서 비슷한 옷만 산다.

"안 입어보던 브랜드 옷을 사고 싶을 때, 사이즈 실패 걱정 없이 나에게 맞는 걸 골라 새로운 모습에 도전한다."

03 · 차별점 · 해자
  • 몰 교차 — 플랫폼 울타리를 넘어 브랜드 간 사이즈를 번역한다. 개별 몰은 구조적으로 못 만드는 데이터.
  • 구매 이력 불필요 — 착용 경험만으로 시작한다. 신규 사용자도 첫 진단부터 결과가 나온다.
  • 중립성 — 직접 팔지 않으니 "건너가게" 도울 동기가 있다.
  • 쓸수록 커지는 실측 — 판정에 올라온 사이즈표를 검수해 정본으로 승격. 커버리지를 사용자 힘으로 채운다.
  • 매칭으로 이어지는 연결 — 진단 결과(브랜드별 사이즈)가 전문가 요청에 자동으로 딸려간다.
04 · MVP 기능 — 이번에 만드는 것
1
AI 체형·사이즈 진단LLM + 규칙
성별·키·몸무게 + 착용경험 보정 + 선호핏 → 카드 3종: 체형 프로필 · 핏 인사이트 · 브랜드별 추천 사이즈. 숫자는 규칙, 말은 AI.
2
구매 판정 (Fit)규칙
진단이 "내 몸"이라면, 판정은 지금 사려는 그 옷 한 벌에 답한다. 사이즈표 캡처(AI 인식)·직접 입력 → 사이즈별 판정. 동의 시 실측 데이터로 승격.
3
전문가 추천 받기페이크도어
실매칭 없이 클릭·오픈알림 신청만 로깅해 유료 전환신호를 측정. 수요부터 확인하고 만든다.
05 · 핵심 플로우 · 측정 배선
진단 입력▸ 서버 엔진 /api/diagnose▸ 결과 카드▸ "맞았나?" 피드백▸ DB feedback▸ kill_metric
판정 입력·캡처▸ /api/judge▸ 사이즈별 판정▸ garment_submission▸ 검수 → 정본 실측

Aha: 진단 카드에서 "평소 입던 옷 기준으로, 한 번도 안 입어본 브랜드인데 이 사이즈면 맞겠다"는 확신이 처음 드는 순간.

엔진 원칙: 숫자는 규칙(재현 가능·검증 가능), 서술만 LLM. 진단은 카테고리 단위(상의·하의). 결과는 덮어쓰지 않고 날짜 스냅샷으로 쌓는다. 엔진은 서버에서만 돈다(클라이언트 미노출 = 해자).

06 · 범위 밖 (지금은 안 만든다)

전문가 실매칭 · 결제/정산 · 8유형 LLM 서술 · 파생 카테고리(아우터·원피스·치마) · SEO 페이지. 하나라도 끌려오면 측정이 늦어진다. ※ 계정·어드민·구매 판정은 측정에 필요해 In으로 편입됨

★ Kill Metric — 성패를 가르는 단 하나
65% 이상
아는 브랜드로 진단했을 때 "실제로 내가 입는 사이즈랑 맞다" 동의율. 실구매 없이 엔진 정확도를 잰다. 미달이면 엔진 교체 또는 중단.
≥50%"안 사본 브랜드도 사보겠다" (페인 해소)
≥25%유료 버튼 클릭률 (전환신호)
07 · 단계 · 비즈니스
Now
진단		데이터 확보. 주요 브랜드 N개 한정 진단 + 판정 수집으로 커버리지 확대. 수익원 —
v2
매칭		수익화. 전문가 실매칭 — 매칭 수수료(B2C) · 커머스 제휴 커미션
v3
확장		데이터 확장. 사이즈 API(B2B·반품 절감) + 상황별(소개팅·면접·결혼식) 과금 · 오프라인 · 퍼스널컬러

North Star: 주간 유료 추천 채택 수. MVP는 그 입구인 번역 정확도 + 유료 전환신호를 검증한다.

08 · 현재 상태 · 2026-07
  • 측정 경로 실배선 완료 — 진단→서버 엔진→DB 적재→정확도 집계까지 연결됨
  • 측정 2축 — ① 진단 정확도(feedback) ② 매칭 수요(lead·페이크도어). session_id로 조인해 진단→수요 전환을 본다
  • 구매 판정 In 편입 — 같은 엔진 재사용이라 측정을 늦추지 않고, 실측 커버리지(최대 제약)를 사용자 힘으로 푼다
  • 어드민 4메뉴 가동 — 사이즈·데이터 / 정확도 추세 / 전문가 수요 / 엔진 강화
  • 스택 — Next.js + Supabase + Vercel, 운영비 $0

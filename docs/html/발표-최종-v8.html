08
MVP v1 · 중간발표

먼저, 없던 기준부터 만들었습니다.

자리는 비어 있었고, 우리는 거기서 시작했습니다 — 첫 MVP는 두 기능이었습니다
기능 01

체형 진단

줄자를 대는 대신 평소 잘 맞는 옷 2벌의 착용 경험에서 몸을 거꾸로 계산합니다. 부위별 치수와 8체형을 뽑아 9개 브랜드의 내 사이즈로 번역합니다.

2분 · 줄자 없이 · 최초 1회
기능 02

스타일 진단 · 전문가 연결

어울림은 정답이 없어 계산으로 풀리지 않습니다. 그래서 체형 진단 결과를 요청서에 그대로 실어 스타일리스트에게 연결했습니다.

전문가가 내 몸을 알고 시작한다
MVP v1 체형 진단  +  스타일 진단 — 여기까지가 중간발표에서 보여드린 내용입니다
09
MVP ① · 체형 진단

MVP ① — 착용 경험만으로 내 체형과 브랜드 사이즈까지

사이즈 축 · 첫 번째 순간소요 약 2분

앞에서 말한 역산이 실제로 어떻게 도는지 보여드리겠습니다. 입력은 옷 2벌의 착용 경험뿐입니다.

① 착용 경험 입력
② 8체형 진단 결과
③ 브랜드별 추천 사이즈
1
"유니클로 오버핏 S를 입어요"
기본 정보 4개 + 평소 입던 옷 1~3벌과 부위별 느낌(끼임/딱맞음/여유/큼). 이 착용 경험이 줄자를 대신합니다.
2
내 몸을 거꾸로 계산
그 옷의 실측치에서 여유(옷−몸)를 역산 → 부위별 몸 치수 → 8체형으로 분류. 근거는 사이즈코리아 제8차 인체치수조사 회귀 모델입니다.
3
안 입어본 브랜드로 번역
계산된 몸을 9개 브랜드 · 1,679행 실측표에 대입 — 브랜드마다 다른 사이즈가 '딱맞음 %'와 병목 부위까지 함께 나옵니다.
✓
정확도 검증 루프
결과 화면의 "맞아요 / 보통 / 안 맞아요"를 진단 ID와 함께 DB에 적재 — 킬 메트릭(동의율 65%)을 실측합니다.
10
MVP ② · 스타일 진단

MVP ② — 정답이 없는 스타일은, 사람에게 연결합니다

스타일 축 설문 40%실매칭 수요 검증 단계

체형은 계산으로 풀었습니다. 그런데 “뭘 사야 어울리는지”는 규칙으로 계산되지 않습니다 — 정답이 없는 문제라서요. 그래서 사람에게 넘겼습니다.

① 스타일리스트 찾기 · 견적 요청
② 견적서에 체형이 자동 첨부
★
사이즈 축과 스타일 축을 잇는 고리
진단 결과(8체형 · 부위별 예상 치수 · 상하의 핏 취향)가 견적서에 그대로 실립니다. 스타일리스트가 체형을 모르는 채 시작하지 않습니다.
1
지금은 수요부터 측정합니다
공급자를 먼저 모으면 콜드 스타트에 빠집니다. 그래서 배포본은 페이크도어 — "오픈 알림 신청(이메일)"으로 전환 신호만 받습니다. 목표 25% 이상.
2
뒤쪽은 이미 만들어 두었습니다
요청 → 견적 → 안전결제 → 결과물 전달 → 정산 → 분쟁까지 데모로 동작합니다. 수요가 확인되면 여는 것만 남습니다.

Growth Loop

그리고 판정은, 쓸수록 똑똑해집니다

수집 → 검수 → 정본 승격

브랜드 실측을 팀이 손으로 모으면 한계가 분명합니다. 그래서 판정을 쓰는 과정 자체가 데이터를 모으는 과정이 되게 했습니다.

1

사용자가 올린다

판정하려면 어차피 사이즈표를 올려야 합니다. 동의한 경우에만 저장합니다.

동의는 선택 · 판정은 동의 없이도 작동
→
2

운영자가 검수한다

잘못된 실측이 정본에 섞이면 추천과 판정이 통째로 흔들립니다. 사람이 한 번 거릅니다.

대기 · 승인 · 반려 · 병합
→
3

정본으로 승격된다

승인된 사이즈표가 브랜드 실측 DB에 편입되고, 다음 진단·판정에 바로 반영됩니다.

→
4

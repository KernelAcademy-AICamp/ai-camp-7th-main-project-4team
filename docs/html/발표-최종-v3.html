02
What We Built

핏팅은 이 질문에 답하는 서비스입니다

기능 3가지

먼저 무엇을 만들었는지만 짧게 보여드리고, 왜 이 셋이어야 했는지를 지금부터 말씀드리겠습니다.

1

체형 진단

줄자 없이 평소 입던 옷 2벌로 내 몸을 계산하고, 안 입어본 브랜드의 사이즈까지 번역합니다.

2

구매 판정 (Fit)

사려는 그 옷의 사이즈표를 올리면 사이즈별로 맞을지 판정합니다. 우리 DB에 없는 브랜드여도요.

구현 · 배포 완료
3

스타일리스트 연결

사이즈가 아니라 "뭐가 어울리는지"가 고민이라면, 내 체형을 들고 전문가에게 갑니다.

08
Existing Solutions & Limits

이미 나와 있는 해결책들, 그리고 멈추는 지점

①② 사이즈 축 기존 해결책

아무도 방치한 게 아닙니다. 세 방식이 이미 쓰이고 각각 효과가 있습니다 — 다만 새 브랜드로 넘어가는 순간 셋 다 멈춥니다.

Solution A

몰 자체 사이즈 추천

무신사 등은 내 구매 이력을 근거로 "당신은 이 상품 L"을 알려줍니다. 이력이 쌓인 사용자에겐 꽤 정확합니다.

Limit
구매 이력이 있어야 작동합니다. 처음 가는 몰에선 아무것도 안 나옵니다 — 정작 그때가 제일 불안한데요.
Solution B

비슷한 체형 리뷰

"175/70인데 L이 딱 맞아요" 같은 체형 후기를 참고합니다. 사람이 쓴 실착 정보라 신뢰감이 있습니다.

Limit
같은 175/70이어도 비율이 다릅니다. 후기마다 말이 갈려, 많이 볼수록 더 혼란스러워집니다.
Solution C

상세 사이즈표(cm)

브랜드가 부위별 실측치를 공개합니다. 숫자가 있으니 이론상 가장 정확한 정보입니다.

Limit
내 몸 치수를 모르면 읽을 수 없습니다. "가슴단면 52cm"가 나에게 큰지 작은지 판단할 기준이 없습니다.
Root Cause · 5 Whys 결론
브랜드를 가로질러, 지금 내 몸을 기준으로 번역해주는 곳이 없다
③ 스타일 축은
기존 해결책이 아예 없습니다 — 90%가 전문가를 써본 적 없음

Demo 01 · Size Diagnosis

시연 ① — 착용 경험만으로 내 체형과 브랜드 사이즈까지

문제 ①에 대한 답소요 약 2분

몸을 재서 옷을 찾는 게 아니라, 평소 잘 맞는 옷에서 몸을 거꾸로 계산합니다.

① 착용 경험 입력
② 8체형 진단 결과
③ 브랜드별 추천 사이즈
1
"유니클로 오버핏 S를 입어요"
기본 정보 4개 + 평소 입던 옷 1~3벌과 부위별 느낌(끼임/딱맞음/여유/큼). 이 착용 경험이 줄자를 대신합니다.
2
내 몸을 거꾸로 계산
그 옷의 실측치에서 여유(옷−몸)를 역산 → 부위별 몸 치수 → 8체형으로 분류. 근거는 사이즈코리아 제8차 인체치수조사 회귀 모델입니다.
3
안 입어본 브랜드로 번역
계산된 몸을 9개 브랜드 · 1,679행 실측표에 대입 — 브랜드마다 다른 사이즈가 '딱맞음 %'와 병목 부위까지 함께 나옵니다.
✓
정확도 검증 루프
결과 화면의 "맞아요 / 보통 / 안 맞아요"를 진단 ID와 함께 DB에 적재 — 킬 메트릭(동의율 65%)을 실측합니다.

Step 01 · 측정

킬 메트릭 집계

목표 ≥ 65%
Step 02 · 분해

어디서 틀렸나

정확도를 신뢰도 × 8체형 × 브랜드 × 부위로 쪼갭니다. "확신했는데 틀린 것"이 1순위 수정 대상입니다.

캘리브레이션 히트맵
Step 03 · 개선

엔진 강화 작업목록

진단 로그(불편했던 부위·자유서술)를 사람이 할 일 목록으로 바꿉니다 — 실측 보정 · 규칙 튜닝 · 데이터 수집.

자동 학습이 아니라 우선순위
Step 04 · 성장

데이터가 스스로 는다

Process · 협업

문서를 코드 옆에 두었습니다

기획 문서·화면 정의·의사결정 기록을 같은 저장소에 두고, 화면 현황판은 코드에서 자동 생성합니다.

Stack · 운영비

운영비 $0으로 실서비스 구조

정적 프론트 + 서버 API + Supabase(Postgres). 브랜드 실측표는 서버에만 두어 노출되지 않게 했습니다.

진단·판정 계산도 서버에서 — 데이터가 곧 자산이기 때문입니다.

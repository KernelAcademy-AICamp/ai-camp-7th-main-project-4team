Existing Solutions

이미 나와 있는 해결책들, 이렇게 작동합니다

조사 대상 몰 추천 · 리뷰 · 사이즈표

아무도 이 문제를 방치한 게 아닙니다. 이미 세 가지 방식이 쓰이고 있고, 각각 실제로 효과가 있습니다.

Solution A

몰 자체 사이즈 추천

무신사 등은 내 구매 이력을 근거로 "당신은 이 상품 L"을 알려줍니다. 이력이 쌓인 사용자에겐 꽤 정확합니다.

작동 원리 · 같은 몰에서 산 옷의 사이즈 패턴

Solution B

비슷한 체형 리뷰

"175/70인데 L이 딱 맞아요" 같은 체형 후기를 참고합니다. 사람이 직접 쓴 실착 정보라 신뢰감이 있습니다.

작동 원리 · 나와 비슷한 사람의 경험 대입

Solution C

상세 사이즈표(cm)

브랜드가 부위별 실측치를 공개합니다. 숫자가 있으니 이론상 가장 정확한 정보입니다.

공통점
셋 다 "옷 쪽 정보"이거나 "남의 몸 정보"입니다 — 정작 내 몸은 아무도 모릅니다
07
The Limits · Root Cause

그런데 새 브랜드로 넘어가는 순간, 셋 다 멈춥니다

5 Whys 근본원인 도출

저니맵 최저점(③ 사이즈 결정)을 5번 파고들었더니, 세 해결책의 한계가 한 지점으로 모였습니다.

Limit A

그 몰 안에서만 작동

구매 이력이 있어야 추천이 나옵니다. 처음 가는 몰·처음 보는 브랜드에서는 아무것도 나오지 않습니다. 정작 그때가 제일 불안한데도요.

이력 없음 = 추천 없음
Limit B

남의 체형은 내 기준이 아니다

같은 175/70이어도 어깨·가슴·배 비율이 다릅니다. 그래서 후기마다 말이 갈리고, 많이 볼수록 더 혼란스러워집니다.

표본이 늘어도 확신은 안 늘어남
Limit C

숫자는 있는데 대조군이 없다

사이즈표는 정확하지만 내 몸 치수를 모르면 읽을 수 없습니다. "가슴단면 52cm"가 나에게 큰지 작은지 판단할 기준이 없습니다.

읽을 줄 몰라서 못 씀
Root Cause · 5 Whys 결론
브랜드를 가로질러, 지금 내 몸을 기준으로 사이즈를 번역해주는 곳이 없다

Our Approach

그래서 우리는 거꾸로 풀었습니다

핵심 착용 경험 역산

몸을 재서 옷을 찾는 게 아니라, 평소 잘 맞는 옷에서 몸을 거꾸로 계산합니다. "유니클로 오버핏 S가 어깨는 딱, 배는 좀 낀다" — 이 한 줄이 줄자를 대신합니다.

차별점 01

몰을 가로지른다

특정 몰에 속하지 않으니 브랜드 A의 경험을 브랜드 B로 번역할 수 있습니다. 개별 플랫폼은 자기 울타리 안에 갇혀 구조적으로 못 하는 일입니다.

무신사 M → 자라는 몇?
차별점 02

구매 이력이 필요 없다

기억나는 옷 2벌이면 충분합니다. 그 몰에서 산 적 없어도, 오늘 처음 온 사용자여도 바로 진단됩니다.

첫 방문 · 2분 · 로그인 불필요
차별점 03

중립적이다

우리는 옷을 팔지 않습니다. 그래서 "이 브랜드로 건너가도 된다"고 말할 동기가 있습니다. 파는 쪽은 그 말을 하기 어렵습니다.

판매자가 아니라 번역자
기술적 근거 (해자)
사이즈코리아 제8차 인체치수조사 기반 회귀 모델  ×  브랜드 실측 사이즈 DB — 숫자는 규칙으로 계산하고, 설명 문장만 AI가 씁니다(검증 가능하게)

1
"유니클로 오버핏 S를 입어요"
기본 정보 4개(성별·나이·키·몸무게) + 평소 입던 옷 1~3벌과 부위별 느낌(끼임/딱맞음/여유/큼). 이 착용 경험이 줄자를 대신합니다.

What We Do With It

나온 문제를 고칠 수 있는 것과 아닌 것으로 갈랐습니다

원칙 지금 못 푸는 건 그렇다고 말한다

"좋다는 반응이 많았다"로 끝내지 않았습니다. 11명으로 답할 수 있는 것과 없는 것을 먼저 나눴습니다.

구분사용자가 겪은 문제우리의 대응왜 이 판단인가
지금 고침 브랜드 목록이 좁다 — 탑텐·유니클로 등이 없고, "목록에 없음"이 스크롤에 숨음 (4명) 주요 브랜드 추가 + "목록에 없음"을 버튼형으로 노출 가장 싸고 효과가 큼 — 입력 단계에서 이탈이 생기면 뒤가 다 무의미
지금 고침 결과 화면 정보 과부하 — "갑자기 너무 많은 정보" (2명) 첫 화면은 체형 + 추천 사이즈 한 줄, 나머지는 접기 만족도 최하(3.88) 화면 · 정보를 줄이는 게 아니라 순서를 정하는 문제
확인 후 정확도 실패 — "체구가 작은데 XL을 추천" (1명) 해당 응답을 역추적해 엔진에서 재현 · 원인 나오기 전까지 정확도 홍보 금지 킬 메트릭 직결이라 추측으로 덮으면 안 되는 항목
전략 먼저 신뢰가 낮다 — "사진 없이 진단해서 못 믿겠다 / 실측을 직접 넣고 싶다" (다수) 실측 직접 입력 옵션(개발 가능) · 아바타 시각화(v2 논의) — 방향은 "내 몸을 더 반영" UI 문제가 아니라 방향 문제 — 정하지 않고 화면만 고치면 같은 지적이 반복됨
못 푼다 실사용 전환이 낮다 — 실사용 3.38 (근본) UT로는 결론 내지 않음 → 배포 데이터로 판단 8~11명으로 전환율은 측정할 수 없음 · "다들 좋다고 했다"로 결론 금지
우리가 한 실수
테스트 도중에 결과 화면을 바꿔서 8명과 3명의 데이터가 섞였습니다 — 다음 UT는 빌드를 고정하고 시작합니다
그래서 배운 것
레이아웃을 바꿔도 실사용 점수는 그대로였습니다. 지렛대는 화면이 아니라 신뢰였습니다

## 1. 한 줄 요약

새 브랜드 옷을 사고 싶어도 "내 사이즈가 맞을지" 몰라 주저앉는 사람에게, 평소 입던 옷의 착용 경험을 기준으로 **브랜드를 가로질러 내 사이즈를 번역해주는** AI 진단 카드. 진단으로 사용자·사이즈 데이터를 모아, 그 위에 스타일리스트 매칭을 얹어 확장한다.

> 표지 카피: *"브랜드를 가로질러 '내 사이즈'를 번역한다 — 사이즈 고민을 넘어, 새로운 나를 입다."*

## 2. 문제 정의

새 브랜드로 건너가려는 사람은 "이 브랜드에서 내 사이즈가 뭔지"를 몰라 망설인다. 무신사 등은 이미 사이즈 추천을 하지만 *자기 몰 안 + 구매 이력*에 갇혀 있어, 새 몰·새 브랜드로 넘어가는 순간엔 아무도 번역해주지 않는다. 결국 실패가 두려워 늘 사던 브랜드의 비슷한 옷만 다시 사게 된다.

> 차별점이자 해자: ① 몰 교차 ② 구매 이력 불필요(착용경험 기반) ③ 중립성 — 직접 팔지 않으니 건너가게 도울 동기가 있고, 몰을 가로지르는 사이즈 데이터는 개별 플랫폼이 구조적으로 못 만든다(무신사는 자기 울타리 안에 갇힘).

## 3. 가설 — 왜 사이즈를 도구로 푸는가

새 옷 구매가 막히는 이유(설문): **스타일 어울림 40% / 사이즈 적합 38%.** 두 축이 거의 반반이라 하나만 풀면 절반의 사용자만 잡힌다. 성질이 다르니 푸는 주체도 다르게 —

- **스타일**은 정답이 없다 → **전문가**가 푼다 (후속 가설: 스타일리스트 매칭).
- **사이즈**는 정답이 있다 → **도구**가 푼다 (지금의 심장: 번역 엔진).

## 6. North Star / Aha

- **North Star Metric:** 주간 유료 추천 채택 수. 본 MVP는 그 입구인 **사이즈 번역 정확도 + 유료 전환신호**를 검증한다.
- **Aha Moment:** 진단 카드에서 *"평소 입던 옷 기준으로, 한 번도 안 입어본 브랜드인데 이 사이즈면 맞겠다"*는 확신이 처음 드는 순간.

## 7. MVP 기능 (3개)

- **AI 체형·사이즈 진단 [LLM + 규칙]** — 입력: 성별·키·몸무게·나이 + *입어본 옷 착용경험 보정* + 선호핏. 출력 카드: ① 체형 프로필(캐릭터) ② 핏 인사이트 ③ **주요 브랜드별 추천 사이즈**.
- **구매 판정(Fit) [규칙]** — 진단이 "내 몸"을 알려준다면, 판정은 **지금 사려는 그 옷 한 벌**에 답한다. 상품 사이즈표를 캡처(AI 인식)하거나 직접 입력해 올리면 내 체형에 대보고 **사이즈별로 맞을지** 판정. 동의하면 그 사이즈표를 모아 실측 데이터로 승격 — **쓸수록 데이터가 늘어나는 구조**.
- **전문가 추천 받기 (페이크도어)** — 버튼 클릭·오픈 알림 신청만 로깅해 유료 전환신호 측정(실매칭 X). 수요부터 확인.

## 8. 단계적 범위 · 비즈니스 (Now / Next)

*"데이터 확보 → 수익화 → 데이터 확장"의 사업 단계.*

- **Now(MVP) · 진단:** 진단으로 사용자·사이즈 데이터 확보(주요 브랜드 N개 한정). **판정에 올라온 사이즈표를 검수해 정본 실측표로 승격** — 사용자가 쓸수록 브랜드 커버리지가 늘어나는 수집 경로. 수익원 —.
- **v2 · 매칭:** 전문가 실매칭으로 수익화 — 매칭 수수료(B2C)·커머스 제휴 커미션.
- **v3 · 확장:** 축적 데이터를 사이즈 API(B2B, 쇼핑몰 반품 절감)로 확장 + 상황별(소개팅·면접·결혼식·여행 등) 카테고리·오프라인·퍼스널컬러. 상황은 페인·지불 의향이 집중되는 지점이라 매칭의 과금 단위가 된다. 수익원 — 데이터 API·상황별 과금.

## 9. 성공 기준

- ★ **킬 메트릭** — 추천 사이즈가 "내가 실제 입는 사이즈와 맞다" 동의율 **≥ 65%** (아는 브랜드로 검증 → 실구매 없이 엔진 정확도 확인. 미달 시 엔진 교체/중단).
- 보조: "안 사본 브랜드도 사보겠다" 의향 ≥ 50%(페인 해소) / 유료 클릭률 ≥ 25%(전환신호).

## 10. 열린 질문

- 체형·사이즈 추정 로직(규칙 vs LLM vs 혼합) — *이 MVP가 킬 메트릭으로 답할 것.*
- 착용경험 보정 몇 벌·어떤 부위.
- 브랜드 실측 확보·정규화(차별점이자 최대 난관).
- 페이크도어 클릭의 허수 보정.

## 11. 한 장 기획서 v0.2 — 좁히기 부록

### 11-1. 또렷한 아이디어 한 줄

> **온라인으로 SPA 브랜드 옷을 사면서 안 입어본 브랜드는 사이즈가 무서워 늘 사던 곳만 다시 사는 사람이**,
> **사이즈표·후기 눈대중 대신 평소 입던 옷 2~3벌의 착용 경험을 입력해**,
> **브랜드별 추천 사이즈 한 장을 받아**,
> **"이 브랜드면 이 사이즈" 확신으로 안 사보던 브랜드를 결제한다.**

측정: 아는 브랜드로 검증했을 때 **"내가 실제 입는 사이즈와 맞다" 동의율 ≥ 65%**(§9 킬 메트릭), 보조로 "안 사본 브랜드도 사보겠다" ≥ 50%.

> 좁힘 근거 — "직장인·누구나"를 뺀 자리에 ① 온라인 구매 ② SPA 앵커 브랜드 보유(유니클로·자라·무신사스탠다드 등 [6_사이즈엔진.md](6_사이즈엔진.md) A축 대상) ③ **브랜드를 건너가려다 멈춘 경험**이라는 세 조건을 넣었다.

### 11-4. MVP 기능 (Must have) · MoSCoW

**한 문장 정리 — 사용자가 *평소 입던 옷을 알려주고*, *브랜드별 추천 사이즈와 "이 옷이 맞을지" 판정*을 받는다.**

| 칸 | 항목 | 비고 |
|---|---|---|
| **Must** | ① **AI 체형·사이즈 진단** — 착용경험 → 브랜드별 추천 사이즈 카드 | 킬 메트릭(§9)이 붙는 기능 |
| **Must** | ② **구매 판정(Fit)** — 상품 사이즈표 캡처/입력 → 사이즈별 판정 | 같은 엔진 재사용 + 사이즈표 수집 경로 |
| **Must** | ③ **전문가 추천 페이크도어** — 클릭·알림신청만 로깅 | 유료 전환신호 측정(실매칭 X) |
| **Should** | 결과 근거 표시 강화(원리 배지·추천별 근거 한 줄) · 브랜드 목록 확대 | UT S1·U1 |
| **Could** | 계정·즐겨찾기·내 기록 보관 | 플래그 off 상태로 존재 |
| **Won't** | 11-5 목록 전체 | — |

> **강의 기준은 "Must 2개"인데 왜 3개인가** — 셋이 **서로 다른 질문**에 답하기 때문이다. ①은 *엔진이 맞나*, ②는 *특정 상품에 답할 수 있나*, ③은 *돈 낼 사람이 있나*. ②·③은 ①의 엔진·화면을 **재사용**해 추가 개발비가 작고, ②는 실측 커버리지(측정의 최대 제약)를 사용자 힘으로 푸는 수집 경로를 겸한다([마일스톤1](마일스톤1-측정가능MVP.md) §0 각주와 동일한 판단).
> 굳이 둘로 더 줄여야 한다면 잘라낼 순서는 **③ → ②**(③은 버튼 하나라 언제든 다시 붙일 수 있음).

### 11-5. Won't have — 의도적으로 안 하는 것

| 안 하는 것 | 왜 지금은 안 하나 |
|---|---|
| **전문가 실매칭·결제** | 수요(페이크도어 클릭)부터 확인. 매칭은 v2 수익화 단계(§8) |
| **사진·아바타 기반 체형 측정** | UT에서 요청 나왔지만(S1) 큰 건 — 진단 정확도 검증이 먼저 |
| **줄자 실측 직접 입력을 주 입력으로** | 재는 사람이 적어 이탈. prior + 착용경험이 핏팅의 방식 |
| **파생 카테고리(아우터·치마·원피스) 실착 잠금** | 기반(상·하의)으로 체형을 잠그고, 파생은 선호핏만 |
| **퍼스널컬러·상황별(소개팅·면접) 카테고리** | v3 확장. 지금 넣으면 서비스 정체성이 흐려짐(UT S2) |
| **B2B 사이즈 API** | 데이터가 쌓인 뒤(v3) |
| **브랜드 실측표(garments) 공개 노출** | 수집 증거·해자 유출. 서버 전용으로만 사용 — 전략적 금지 |
| **로그인 강제** | 진단은 비로그인으로 끝나야 함. 계정은 선택 |

### 11-6. 현재 대안 (경쟁 서비스 3개)

| 대안 | 어떤 사람이 왜 쓰나 | 우리가 비는 지점 |
|---|---|---|
| **무신사 사이즈 추천** (몰 내장) | 무신사에서 자주 사는 사람. 구매 이력이 쌓이면 꽤 맞음 | 자기 몰 안 + 이력 필요 → **새 몰·새 브랜드로 못 건너감** |
| **브랜드 자사몰 사이즈표 + 후기** (유니클로·자라 등) | 살 브랜드가 정해진 사람 | 내 몸 치수를 모르면 표를 대조할 수 없음. 후기는 체형이 제각각 |
| **오프라인 시착 후 온라인 구매** | 실패가 두려운 사람의 최종 수단 | 시간·이동 비용. 매장 없는 브랜드엔 아예 못 씀 |

> ※ **주말 과제** — 위 3개를 직접 가입·사용해 첫 5분 스크린샷과 "어디가 별로인지" 한 줄씩을 이 표에 채운다(현재 칸은 문서·설문 근거이지 실체험 메모가 아님).

### 11-7. 다음 목표 (한 줄)

## 1. 다른 PC에서 시작하기

```bash
npm test                          # 엔진 골든 테스트 115건 — 초록불이면 정상
npm run serve                     # :8000 정적 서버(proto 모드 = 화면 개발용)
npm run dev:api                   # :3000 web/ + /api/* (api 모드 = 서버 라우트 포함)
git status && git log --oneline -3   # 브랜치가 dev-working인지, 미커밋 작업이 없는지
```

작업 브랜치는 **`dev-working`** 고정입니다(역할별 개인 브랜치 — 작업마다 새로 파지 않음).

### 1.1 폴더를 통째로 복사해 옮기는 경우

**따라가는 것** — `.git`(전체 이력·브랜치), `.env.local`(**키 포함**), `.vercel/`(프로젝트 연결), `app/`(빌드 산출물), `data/**/raw/`(수집 원본).

> ⚠️ **`.env.local`에는 `SUPABASE_SECRET_KEY`(RLS 우회 · DB 전권)와 `ANTHROPIC_API_KEY`가 들어 있습니다.** git에는 없지만 **폴더 복사에는 따라갑니다.** USB·클라우드 드라이브를 거친다면 그 경로에 키가 남는다는 뜻입니다. 옮긴 뒤에는 전달 매체에서 지우고, 공용 PC라면 아예 `.env.local`을 빼고 옮긴 뒤 따로 받으세요.

**안 따라가는 것 — 새 PC에서 다시 해야 함**

| 항목 | 조치 |
|---|---|
| git 인증(푸시·PR) | HTTPS 자격증명은 OS 키체인에 있어 안 옮겨집니다. `gh auth login` 또는 토큰 재설정 |
| `gh` CLI 자체 | 설치·인증 필요(현재 PC는 `~/.local/bin/gh`에 있고 PATH에 없어 풀패스로 호출) |
| Claude Code 메모리 | 저장소 밖(`~/.claude/…`)이라 안 옮겨집니다. **이 문서가 그 대체물입니다** |
| `node_modules` | 옮겨도 되지만 25MB. 지우고 `npm i`로 복구해도 됩니다(devDependency는 prettier 하나) |

**용량**: 전체 163MB(`.git` 89MB · `node_modules` 25MB · `data` 24MB). `node_modules`·`app`을 빼면 ~115MB입니다.

### 1.2 키 (`.env.local`)

| 키 | 용도 |
|---|---|
| `SUPABASE_URL` · `SUPABASE_SECRET_KEY` | 서버 라우트(`/api/*`)의 DB 접근 |
| `ANTHROPIC_API_KEY` | 판정 사진 첨부 기능(선택) |

클라이언트 공개 키(`SUPABASE_PUBLISHABLE_KEY`)는 `web/js/config.js`에 이미 있어 별도 설정이 필요 없습니다. `npm run serve`(화면 개발)만 할 거면 `.env.local` 없이도 됩니다.

## 2. 반드시 알아야 할 구조 결정 3가지

### 2.1 진단 저장은 '진단 실행' 단위 — 렌더 단위가 아니다

`db/13_diagnosis_run.sql` · PR #105

**과거 사고**: `result.html`이 그려질 때마다 `/api/diagnose`가 행을 INSERT했습니다. 마이 진입·새로고침·계정 하이드레이션의 iframe 리로드 전부가 저장을 유발해, **190건 중 68건이 같은 진단의 복사본**이었습니다(킬메트릭 38% 부풀림. 한 세션이 같은 입력으로 11행을 만든 사례도 있음).

**현재 구조**:

| 층 | 규칙 |
|---|---|
| DB | `diagnosis.run_id` + partial unique `(session_id, run_id, category)` |
| 서버 | `view_only`면 계산만 · 같은 실행이면 기존 행 반환(`reused`) · `23505`는 '이미 저장됨'으로 처리 |
| 클라 | `fitting.dxRun`을 `run_id`로 전송 · `embed`이거나 `dxRun` 없으면 `view_only` |

**`category`를 키에 넣은 이유**: 한 번의 진단 실행이 상의·하의 결과를 각각 남기는 건 정상입니다. **`view_only` 기본값이 '저장'인 이유**: 캐시된 구 클라가 필드를 안 보내는데, "없으면 저장 안 함"으로 만들면 그 브라우저의 진단이 조용히 사라집니다.

> ⚠️ **과거 진단 불러오기(정본 교체) 기능을 만들 때는 이 경계 위에서 만드세요.** 없으면 "옛 진단을 볼 때마다 새 진단이 생기는" 구조가 됩니다.

### 2.2 proto 목업이 실경로로 새는 사고가 3번 반복됐다

같은 사고가 형태만 바꿔 세 번 났고, 매번 "이 경로를 막자"로 고쳐서 다음 경로에서 또 터졌습니다.

1. `demo-session.js`가 api에서 시드 → 실 DB에 가짜 진단(328건 중 144건)
2. `USER` 페르소나(김도현)가 계정 모드로 누출 → 가짜 프로필
3. **이미 심긴 시드를 api에서 소비** → DB에 13건 유입 + 로그인 시 계정 귀속. 게다가 하이드레이션이 그 행을 다시 세션에 넣어 **자기복제**(원본 시드 없이도 증식)

**현재 방어선**:
- 목업 시드에 소유 표식(`fitting.demoSeed`) — api 모드에서는 **치우고** 시작(안 심는다가 아니라)
- 사용자가 직접 입력하면 표식 해제(`diag-basic.js`)
- 서버가 `basic.age`가 **숫자면 400**으로 거부 — 실제 입력은 `'30대'` 같은 문자열만 보냅니다

> ⚠️ **판별 기준을 값 조합(172/68·경험0)으로 잡지 마세요.** '경험 0벌 진단'은 정상 지원 플로우라 실사용자를 오탐합니다. `age` 타입만이 무오탐 신호입니다.
>
> ⚠️ **증상보다 DB를 먼저 보세요.** 이 사고를 추적할 때 모드 고정·데모 시드로 두 번 헛짚었는데, `diagnosis` 행 하나만 열어봤으면(`age: 33` 숫자) 한 번에 나왔습니다.

### 2.3 모드 스위치는 탭에 고정된다

`?mode=proto|api`는 `sessionStorage['fitting.mode']`에 저장돼 **그 탭 내내 유지**됩니다. 기본 주소로 돌아가도 안 풀립니다(저장값이 기본값을 이김).

- 배포본에서 proto로 들어가면 **진단 추천이 비어 보입니다** — 실측표(`garments.json`)를 배포하지 않기 때문(해자 보호). 버그가 아닙니다.
- 그래서 proto일 때 **좌하단에 표시 배지**를 띄웁니다(`실서비스 →` 링크로 복구).
- `?accounts=on` 오버라이드는 **프로덕션 빌드에서 제거**됩니다(`gen-app`). 로컬에서만 씁니다.

## 5. 함정 목록

- **`_reset.html`은 `fitting.mode`·`fitting.accounts`를 남깁니다.** 사용자 데이터가 아니라 "이 탭이 어느 모드인지"라 지우면 계정 모드가 proto로 튕깁니다(`index.js`의 `wipeLocal()`도 같은 이유로 되살림).
- **`restoreNav()`는 세션 판정 전에 결론 내지 않습니다.** 계정 모드의 세션 복원은 비동기라, 판정 전의 '비로그인'은 결론이 아닙니다(`_authReady`·`_navPending`).
- **로그인 의도 마커는 `localStorage`입니다.** 매직링크는 새 탭에서 열려 `sessionStorage`로는 안 건너옵니다. 유효기간 30분.
- **탈퇴해도 `user_id`는 남습니다.** 계정·개인정보는 파기되고 세션 식별자는 마스킹되지만, 진단이 그 id로 묶여 있습니다. 비식별의 정의를 어디까지 볼지는 법적 검토 대상입니다.
- **`web/data/*.json`은 생성물입니다.** 손으로 고치지 말고 소스+생성기로 재생성하세요(예외: `bodytypes.json` — 디자이너 직접 관리).
- **`app/`은 빌드 생성물**(gitignore)입니다. `npm run gen-app`으로 만들며 소유자가 없습니다.

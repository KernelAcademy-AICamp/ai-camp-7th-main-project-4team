# 결과 화면에 "신뢰 근거(show your work)" 추가 요청

> UT(11명) 신뢰 3.38 개선 작업. 개선리스트 S1의 해결 방향. 다른 세션/담당에게 넘길 작업 프롬프트.

## 왜 (배경)
사용성 테스트(11명) 결과, "이 서비스 결과를 신뢰한다"가 3.38/5로 낮았음.
서술을 모아보니 뿌리는 하나 — **"내 몸이 결과에 반영됐다는 느낌이 안 든다."**
지금 결과 화면이 "당신은 OO 체형, 추천 M"처럼 **결론만** 주고 근거를 안 보여줘서임.
→ 결과가 어떻게 나왔는지 **계산 과정을 보여주면(show your work)** 신뢰가 붙는다.

참고 시안(이 방향대로): https://claude.ai/code/artifact/208ba3b0-de12-4a93-9602-64a96c070601

## 뭘 (3가지 추가 — 순서대로)

**① 상단 "원리 배지" (결과 상단에 1회)**
- 위치: 체형 요약 / "FITTING의 한 끗" 아래, 브랜드별 추천 사이즈 위
- 내용: "이 진단이 나온 방식 — ① 입어본 옷 → ② 체형 역산 → ③ 브랜드 번역"
      + "별점·후기가 아니라 당신이 직접 입어본 옷의 느낌으로 계산했어요. 추측이 아니라 역산이에요."
- ※ 카피는 새로 쓰지 말고 web/about.html의 "3단계 원리"·"왜 우리 추천이 맞다고 믿나요?" 문구 재활용.

**② 추천별 "근거" 한 줄 (핵심)**
- 위치: "브랜드별 추천 사이즈" 리스트에서 각 브랜드 추천 막대(s2row) 바로 밑
- 내용: 그 사이즈가 왜 나왔는지 한 줄. 데이터는 아래 3개를 조립 —
  1. 사용자가 입력한 앵커 옷(브랜드·사이즈) — fitting.dx 에서
  2. 역산된 체형 치수(어깨·허리 cm) — 체형 측정 계산값에서
  3. 병목 부위(r.bottleneck) — 이미 추천 데이터에 있음(어느 부위가 사이즈를 갈랐나)
- 예) "↳ 근거: 당신이 넣은 '유니클로 L·어깨 딱맞음·허리 여유'를 어깨42·허리80으로 역산 → 여기선 M (허리가 갈랐어요)"

**③ 하단 피드백 "맞았나요?"**
- 위치: 추천 리스트 아래
- 내용: "이 추천, 실제로 맞았나요? [잘 맞음][애매함][안 맞음]" + "당신 답이 진단을 더 정확하게 만들어요"
- 엔진은 이미 fitting.feedback을 받으니 기존 피드백 로직에 화면만 연결.

## 데이터 (확인 끝 — 다 가져올 수 있음)
- r.bottleneck(병목 부위)은 추천 데이터에 **이미 있음** → 그대로 사용.
- 입력 앵커 옷(fitting.dx)·역산 치수(체형 측정 계산값) 둘 다 추천 렌더 시점에 **가져올 수 있음(확인됨)**.
  → ②의 근거를 풀 버전("입력 옷 → 역산 치수 → 결론 + 병목")으로 작성.

## 하지 말 것 / 주의
- 기존 "FITTING의 한 끗"(result.js의 t.insight)은 **건드리지 말 것.**
  그건 스타일 서술, 이번 '근거'는 사이즈 계산 설명 — 목적이 다름. 대체·이동 X, 별도 신규 추가.
- 파생 카테고리(추천이 '준비 중'인 경우)에는 근거를 붙이지 말 것. 실계산(TOP/BOTTOM)에만.
- 색·간격은 web/css/tokens.css 변수만 사용(하드코딩 금지).
- 마크업=result.html, 렌더 로직=web/js/result.js. 둘 다 손대면 디자이너·개발 소유 경계 겹치니 변경 공유.
- CSS/JS 수정 후 캐시버스트 스탬프(npm run stamp-assets; 이 PC는 Node로 직접 ?v= 갱신).
- 커밋·푸시는 사용자 요청 시에만.

## 급하면 우선순위
②(근거)가 핵심. 시간 없으면 ②만 먼저, ①③은 나중.
